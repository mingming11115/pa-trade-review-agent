# PA Market Analysis Demo

PA Market Analysis Demo 是一个面向交易复盘、行情分析和任务编排的全栈应用。
项目由 **FastAPI 后端** 和 **React + Vite 前端** 组成，支持 K 线行情展示、交易复盘、实时分析、分析历史管理、提示词管理、个人模型配置等能力。

> 免责声明：本项目中的分析结果仅用于研究与复盘，不构成投资建议。

## 主要功能

- **行情分析看板**：支持 ES / NQ 等品种的多周期 K 线展示与分析
- **历史复盘**：基于交易记录自动生成复盘窗口并进行分析
- **实时分析**：针对实时行情进行持续轮询与自动触发分析
- **分析历史管理**：查看、筛选、重试、收藏和恢复历史分析结果
- **交易日志管理**：支持手工录入交易、导入 Excel / CSV 交易文件
- **回放交易**：直接在原 K 线回放中买卖、管理四类订单，退出时保存，并从回放记录继续或分析
- **真实交易回放**：在原工作台回放已有交易的开平仓、持仓与盈亏，可从交易日志进入
- **追问助手**：围绕已完成分析结果继续追问和补充判断
- **提示词管理**：所有用户可在线编辑个人数据库提示词，查看历史并回滚
- **个人中心**：管理模型配置、Token 用量与导入记录
- **预警规则**：支持价格/收盘类告警规则配置

## 本地运行

### 1. 准备环境

请先安装：

- Python 3.11+
- Node.js 18+
- PostgreSQL

### 2. 配置环境变量

复制并修改环境变量示例文件：

```bash
cp .env.example backend/.env
```

根据你的实际环境修改以下配置：

- `DATABASE_URL`
- `HIST_BASE_URL`
- `HIST_API_KEY`
- `FRONTEND_ORIGIN`
- `AUTH_REQUIRED`
- `ADMIN_USERNAME`
- `ADMIN_PASSWORD`

### 3. 启动后端

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 4. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端默认运行在 `http://localhost:5173`，后端默认运行在 `http://localhost:8000`。

## K 线内置指标

点击 K 线图工具栏的 **指标**，可在面板的“图表显示”中切换 EMA、Gap、K#、H/L；顶部不再单独摆放这四个开关。也可搜索、收藏并添加 MA、EMA、布林带（BOLL）、MACD、RSI 和成交量。MA/EMA/BOLL 叠加在主图，成交量显示在主图底部，MACD/RSI 使用独立副图。默认开启 EMA20 和成交量，每种指标可添加一次。

图内图例随十字线显示对应 K 线的数值，离开图表恢复最新值；悬停图例可隐藏、设置或删除指标，窄屏直接显示操作按钮。齿轮或双击名称打开独立设置窗口，分为 **参数、样式、可见性**，可调整计算周期、线条颜色/宽度与显示周期。点击 **应用** 生效，取消或 Esc 放弃修改；隐藏保留参数和副图，删除移除指标。

设置和收藏保存在当前浏览器，旧版设置自动迁移。回放时指标只使用当前进度之前的行情；样本不足或成交量缺失时显示 `—`。MACD 柱值采用 `2 × (DIF − DEA)`，RSI 使用 Wilder 平滑。说明与验证见 `docs/issues/builtin-chart-indicators/`。

## 交易回放

交易回放直接使用 PostgreSQL 中已存的分钟行情，不请求外部补数，也不依赖历史行情服务密钥。随机起点从当前品种已有且已确认的数据中选择；指定时间与选 K 线保留选定时刻。历史展示可读取已有稀疏行情；撮合推进只接受连续已确认分钟、已有覆盖证明或明确的常规休市，未知缺口与本地数据边界会明确暂停。

回放的「下一根」和播放按当前图表周期推进，播放固定每秒一根，不显示速度选择、「上一根」或时间定位控件。例如 5m 推进到下一次 5 分钟收盘，内部仍逐分钟撮合，保留中途的成交与止盈止损；未完成的当前柱先补完。

回放默认展示最近 120 根历史 K 线，可加载到 500 根；遇到周末或休市会自动向前补足，保持回放起点不变。最多回溯 30 个自然日，范围内不足时显示已有行情。

回放时图表占满内容区，播放、下一根、周期、时间和退出集中在图下控制栏；持仓、资金统计、订单和成交放在默认收起的 **交易明细**，展开即可管理。窄窗口优先显示图表，任务导航排列在下方；指标副图仍保留独立高度。

交易明细按 **成交记录、持仓、订单、统计** 分页，成交记录默认打开。资金摘要位于表格上方；成交按最新时间排列并统一显示北京时间，买卖方向使用蓝色和红色区分，价格按品种最小变动单位显示。订单支持原有改单、撤单，持仓保护价支持按需修改；窄屏表格可在明细区域内横向滚动。

在原 K 线图点击 **回放 → 选择 K 线**，移动指针预览蓝色起点线及右侧遮罩，点击柱子从该柱开盘时间开始回放；Esc 或取消可退出选择。也可输入历史时间或使用随机起点。开始后图内左上角的 **SELL / BUY** 按所填手数直接提交市价卖出/买入；图旁不再常驻下单表单，右键下单或点击挂单的「改单」时才显示浮层，新单手数与图上输入同步。两侧显示同一个当前回放价，成交沿用设置的滑点和费用。启动区先选起点，再确认必填的初始资金（默认 100000 USD），最后点击「开始回放」；图上选柱只确认起点。盈亏目标、费用和滑点收在「选填设置」，盈亏目标留空表示不限制，达到后仅提示。订单支持市价、限价、止损市价、止损限价，以及撤单、改单、持仓止损止盈和加减仓，不需要单独开启训练。

回放时可在 K 线绘图区 **右键下单**，图内浮层预填价格，支持调整方向、手数和四类订单；右键菜单的 **Reset 重置视图** 恢复图表缩放，不改变进度、订单或持仓。实际成交后，持仓线上显示均价、手数和当前浮动盈亏，旁边的 **平仓** 按钮可按当前回放价立即全部平仓；从 **+ TP / + SL** 拖出保护价，也可继续拖动已有标签，松开即提交，Esc 取消。拖动预览显示对应预计毛盈亏，价格自动对齐最小变动单位；图上修改同步持仓面板，保存后继续回放会恢复。开始编辑或平仓会暂停播放，历史回看时隐藏最新持仓的图上信息。

市价买入、卖出和市价平仓在提交后立即按当前回放价成交，沿用配置的滑点与手续费，不推进行情；成交后图上立即显示持仓。限价、止损市价和止损限价从下一分钟开始按条件撮合；分钟线无法确定有利成交路径时采用保守规则。回看不撤销成交，回到最新进度后可继续下单。退出时选择 **保存并退出 / 不保存退出 / 继续回放**；保存无需先平仓，持仓和挂单一起保留。浏览器刷新后的未保存草稿可从「回放记录」恢复。

左侧 **回放记录** 可查看已保存版本、继续回放或点击 **分析**。继续使用独立草稿，不保存退出不会覆盖原版本；分析使用保存版本的成交、持仓和截止时间以前的行情，结果可以再次查看。保存本身不调用模型。旧版已结束场次可在「旧版已结束回放」中保存并查看。

左侧 **真实交易回放** 及交易日志的「回放」入口保留。

真实回放选择同品种交易，默认覆盖开平仓前后各 60 分钟，可定位到上一笔或下一笔成交。成交标记使用交易原始价格，行情为连续合约，浮动盈亏仅为参考估算；导入报告盈亏不重复扣除费用。已有摘要不能还原未记录的逐次成交。

新增回放表通过现有后端 schema 初始化增量创建；启动或重启后端即可注册接口与表。训练记录与真实交易记录分开，按登录用户隔离；未启用认证时使用现有 local 作用域。不连接实盘，不模拟保证金强平、排队和成交量部分成交。方案、任务与验证见 `docs/issues/trade-replay/`。

## 个人提示词知识库

现有两阶段工作流的提示词可原样导入数据库，建立默认知识条目及第一版历史。分析运行从数据库解析有效内容，并将本次使用的完整内容、版本和摘要保存为不可变快照。两个阶段、重试和同一 Run 的复盘处理共用快照。

先配置 `DATABASE_URL`，再在项目根目录执行显式初始化：

```bash
cd backend
../.venv/bin/python -m app.knowledge.import_prompts
```

导入只创建缺失的条目，不覆盖已存在的内容或版本。重复执行会报告跳过的文件；如果源文件与数据库内容不同，命令报告 `different` 并以退出码 2 结束，需人工核对。退出码 1 表示导入失败。仅导入实际工作流引用的 TXT，不导入 `_reference`。

导入前，正式分析及调试预览会返回知识库未初始化错误；条目缺失或数据库不可用时不会静默回退到文件。原 TXT 保留为导入来源；个人知识库页面直接读取和保存数据库。旧管理员文件 API 保留兼容，文件修改不会覆盖已入库内容。

打开应用后进入 **更多 → 个人知识库**，左侧展示全部 29 份提示词，可搜索文件名并选择编辑、保存、查看版本或回滚；顶部的“阶段与加载说明”打开完整说明页，可选择阶段查看文件用途和加载条件，返回编辑保留草稿。默认显示系统模板，首次修改建立个人初始版本和新修订；保存与回滚仅影响本人的后续分析，已经开始的 Run 保持原快照。普通用户不需要管理员权限。版本冲突或网络失败保留草稿，离开未保存的编辑需确认。历史按页加载。

当前已实现导入、个人在线编辑、历史回滚、运行快照和分析接入。新增条目及加载条件配置见 `todo.md`。未启用认证时所有访问者共用 `local` 作用域；多人部署必须开启认证才能每人独立。

回退旧代码会恢复从 TXT 文件加载，数据库中的知识条目与快照保留。技术方案与验证说明见 `docs/issues/personal-prompt-knowledge-base/`。

## 统一行情归档与后台采集

ES、NQ、MES、MNQ、MGC 的原始分钟线统一保存到 PostgreSQL `market_archive_2023.bars`，SQL 查询视图为 `market_archive_2023.minute_bars`。MES/MNQ 查询各自微型合约，连续合约使用 `.c.0` 日历近月，价格不复权。小时及其他周期从分钟线聚合；旧表中无法由分钟线重建的小时记录仍可兼容查询。

`make market-worker` 启动独立后台采集，`make market-collect-once` 执行一轮。默认每 60 秒处理五个品种；`COLLECTOR_LOOKBACK_MINUTES=30` 重叠修补，`COLLECTOR_MAX_CATCHUP_MINUTES=360` 控制停机后的单批补数。成功查询的覆盖游标与行情同事务提交，休市空窗可推进，上游尚未发布或失败时保留待补窗口。运行与错误可查询 `public.scheduled_job_runs`（job_key 为 `market-minute:*`）和 `public.market_collection_states`。

macOS 服务模板位于 `infra/market-collector/com.pa.market-collector.plist.template`，填入项目、虚拟环境 Python 和日志目录后安装到用户 LaunchAgents。启用独立服务时在项目根 `.env` 设置 `COLLECTOR_MODE=external`，FastAPI 不另启分钟或 WebSocket 循环；`embedded` 则随后端启动。两入口通过 PostgreSQL 锁和调度槽防重复。电脑睡眠或关机期间停止运行，恢复后分批补数。密钥失效时数据保留，失败有记录并退避。

升级旧表先执行 `make market-migrate`：保存完整的 `market_archive_2023.legacy_bars_backup`，迁移并逐字段核对分钟线。未知真实合约 ID 使用 0 且 source 标记 `legacy:*`；查询优先使用真实上游归档。核对及读写验证通过后，显式执行 `cd backend && ../.venv/bin/python -m app.market.migrate_archive --finalize` 移除 `public.market_bars`。程序启动不会重建旧表。备份保留，不压缩。回滚须先停止 worker，恢复旧表及旧版本读写路径；统一归档的数据保留。
