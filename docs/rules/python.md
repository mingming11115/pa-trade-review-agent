# Python 编码规则

## 适用范围

适用于 `backend/` 下的 Python 代码和测试。

## 基本规则

- 使用 Python 3.11+ 支持的语法。
- 新增或修改的公共函数、方法和数据结构必须有准确的类型标注。
- 优先使用清晰、直接的实现，避免为未确认的未来需求提前抽象。
- 函数保持单一职责；复杂逻辑拆成可独立测试的小函数。
- 不使用可变对象作为默认参数。
- 不使用裸 `except:`，只捕获能够处理的异常。
- 不静默吞掉异常；需要降级时记录原因并返回明确结果。
- 业务异常优先使用项目已有的 `AppError` 及其错误码机制。
- 日志和错误信息不得包含密钥、令牌或其他敏感数据。

## 异步规则

- FastAPI 请求链和 SQLAlchemy 数据访问保持异步。
- 不在 `async` 函数中直接执行阻塞 I/O。
- 并发任务必须明确超时、取消和异常处理。
- 共享可变状态必须有清晰的所有者，避免多个协程无序写入。

## 修改要求

- 修改实现前先阅读相关调用方和测试。
- Bug 修复必须添加能够复现问题的回归测试。
- 修改后先运行相关 pytest，再运行后端全量测试。
