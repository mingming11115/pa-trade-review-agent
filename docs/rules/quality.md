# 质量标准

## 适用范围

适用于所有代码修改、测试、Code Review 和交付验收。

## 测试要求

- 新功能必须覆盖正常路径、关键边界和预期失败路径。
- Bug 修复必须先添加能够复现问题的回归测试。
- 测试必须验证可观察行为，避免只验证实现细节。
- 测试应独立、确定且可重复，不依赖执行顺序。
- 修改后先运行局部测试，再运行相关回归测试和全量验证。
- 当前阶段不设置固定覆盖率数字；核心业务规则不得没有测试保护。

## Code Review 标准

Review 至少检查：

- 实现是否满足 Spec 和验收场景。
- 边界条件、异常处理和失败终态是否完整。
- 是否破坏模块边界、公共契约或数据一致性。
- 是否引入安全风险、敏感信息泄漏或破坏性操作。
- 是否出现重复实现、无关重构或不必要依赖。
- 测试是否真实覆盖本次行为变化。

严重正确性、安全性、数据一致性和验收缺失问题必须阻断交付。

## 性能要求

- 避免明显的重复数据库查询、无界循环和无界并发。
- 外部 API、数据库和 LLM 调用必须考虑超时与失败处理。
- 不在请求主链路执行可避免的阻塞操作。
- 性能优化必须基于实际瓶颈或明确指标，不进行猜测式优化。

## 完成门禁

- 没有最新验证结果，不得声称工作完成。
- 后端修改至少运行相关 pytest；前端修改至少运行相关 Vitest。
- 跨端变更需要运行 `make test` 和 `make build`。
- 无法执行的验证必须说明原因、替代检查和剩余风险。
