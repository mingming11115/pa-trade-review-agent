# 依赖管理规则

## 适用范围

适用于 Python、Node.js 及其他生产或开发依赖的新增、删除和升级。

## 选择原则

- 优先使用标准库和项目已有依赖。
- 不为简单功能引入大型依赖。
- 新依赖必须有明确用途，并说明现有方案为什么不能满足需求。
- 优先选择维护活跃、文档完整、许可证兼容且社区成熟的库。
- 避免同时引入功能重复的库。

## 版本规则

- 遵循项目现有版本约束方式，不擅自进行大版本升级。
- 修改依赖时同步更新对应清单和锁文件。
- 不手工编辑锁文件；使用所属包管理器生成。
- 升级前检查破坏性变化，升级后运行相关测试和构建。

## 审批与安全

- 新增生产依赖必须先获得用户批准。
- 不执行来源不明的安装脚本。
- 不在依赖配置中写入密钥或内部地址。
- 发现重复、冲突或存在安全风险的依赖时先报告，不顺手删除。
