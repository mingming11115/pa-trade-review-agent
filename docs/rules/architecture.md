# 架构规则

## 适用范围

适用于后端模块、API、数据库访问、分析工作流以及前后端接口变更。

## 分层职责

- Route/API 层负责请求解析、权限校验、依赖注入和响应适配，不承载复杂业务逻辑。
- Service/Workflow 层负责业务流程和领域规则。
- Repository 层负责持久化操作，不向上层泄漏不必要的数据库细节。
- Pydantic 模型负责输入、输出和跨层数据契约。
- 前端 API 调用集中在 `frontend/src/api.ts`，共享类型集中在 `frontend/src/types.ts`。

## 依赖边界

- 遵循现有模块边界，不跨层直接调用内部实现。
- 不为同一职责创建第二套 Service、Repository 或状态来源。
- 修改公共接口前必须搜索并检查所有调用方。
- API 契约变化必须同步后端模型、路由、前端类型、调用代码和测试。
- 数据库模型变化必须说明数据保留、兼容和回滚方式。

## 分析领域约束

- LLM 输出必须经过结构化校验后才能进入业务流程。
- 分析运行的成功、失败、取消和超时必须保存明确终态。
- 不向用户暴露模型私有思维过程。
- 未经批准不得执行破坏性数据库操作。

## 变更边界

- 只修改当前 Issue 所需的模块。
- 不捆绑无关重构、重命名或格式化。
- 新增架构抽象必须解决当前已存在的问题，并有测试保护。
