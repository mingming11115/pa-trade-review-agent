# 前端工作台重设计

## 目标与已确认方向

用户要求按成熟、常见的前端组件和 UI 设计重新设计现有 PA 前端，已确认「浅色专业交易分析工作台」方向。面向使用 PA 进行行情分析和交易复盘的用户，成功标准是导航清晰、图表突出、结果易读、操作一致，并保留现有业务能力。

用户已查看静态预览并明确要求「按照这个改」。以该预览的浅色、中性边框、蓝色主操作、左导航及图表/结果布局作为视觉基准。预览中的行情、结构、时间和任务数量仅为示例；正式界面不得写入这些示例值，只有现有真实数据支持时才呈现对应指标。

## 范围

- 覆盖主工作台、任务导航、任务配置、分析历史、交易日志、个人中心、管理弹窗及通知的视觉和布局。
- 保留现有路由、API、数据契约、任务执行与取消机制、实时行情与历史回放、图表交互。
- 不新增业务功能，不改后端，不引入主题切换。
- 基于当前工作区实施，保护已有未提交的知识库及分析任务相关修改。

## 设计方案

### 视觉基础

采用 shadcn/ui 风格的轻量组件视觉与 Ant Design 的数据展示原则。使用现有 React 与 CSS 实现统一设计变量和组件样式，本期不新增生产依赖；并非安装 shadcn/ui 或 Ant Design。

背景为冷中性浅灰，内容面板为白色，文字使用深灰，主操作使用低饱和蓝色。绿色、红色、琥珀色仅表达业务状态，状态必须同时有文本。统一边框、8–12px 圆角、4px 基础间距；移除装饰渐变与玻璃效果，仅弹出层使用轻阴影。

正文以 14px 为基础，辅助信息不低于 12px，标题使用 16–20px。价格、数量与时间采用等宽数字；表格数值右对齐。长名称和长结果保持可阅读，不挤压主要操作。

### 工作台布局

顶部保留品牌与全局菜单，压缩为清晰的应用栏。研究与复盘说明保留为低干扰提示。

桌面采用左侧任务导航、中间行情图表、右侧分析结果：导航默认约 240px，可折叠；剩余空间默认约 56% 分配给图表、44% 分配给分析，保留现有拖拽与键盘调整分隔条。图表工具栏集中展示标的、周期和行情状态。执行操作沿用现有入口并统一主次样式，不重复增加按钮。

1024–1279px 使用紧凑导航和自适应面板；小于 1024px 时主要区域改为纵向排列，图表先于结果，不依赖仅悬停可见的控件。窄屏表格局部横向滚动，页面本身不横向溢出。

### 导航与任务

分析任务和复盘任务保持分组及展开行为。统一图标、选中状态、层级缩进与新增入口。按用户本轮已批准的调整，移除顶部独立“新建分析任务”按钮，将唯一分析新增入口放在“K线分析”标题旁，使用与“历史复盘”一致的「＋」按钮，保留可访问名称、禁用条件和回调。任务名称为主信息，标的、周期、运行状态为次信息。折叠导航保留可访问名称和展开操作。

### 分析展示

保留实时、逐根分析、决策图三个视图与现有数据来源。通过标题、摘要容器、分隔线和状态标签突出已有结论，详细证据随后呈现。只调整现有内容的表现，不添加推测结果或伪造数据，不扩大模型推理内容的展示范围。

### 统一交互组件

按钮分主要、次要、文字、危险操作；输入框、选择框、复选框、标签页、表格、弹窗和通知统一高度、间距、边框及焦点样式。禁用、进行中、选中状态可辨识。弹窗保留焦点管理、Escape 关闭与现有可访问名称，长内容在弹窗内滚动。

加载、无任务、无行情、失败、断线和历史数据过期状态使用已有真实状态与操作，统一为简洁的状态展示。动画尊重 prefers-reduced-motion。

## 实施边界

主要涉及 frontend/src/styles.css、App.tsx、SidebarNav.tsx、MoreMenu.tsx；按需调整 TradingChart.tsx 和 DecisionFlowViz.tsx 的视觉配置。优先收敛重复与互相覆盖的 CSS，避免在旧样式末尾不断叠加补丁。不全面拆分 App.tsx 的业务逻辑。

## 验收场景

1. 默认进入实时分析时，用户能辨认任务导航、图表工具栏和分析区域，主要操作具有统一样式。
2. 创建分析或复盘任务后，配置、保存、选择任务与打开运行记录行为与现有流程一致。
3. 有行情和已完成分析时，图表交互及三种结果视图正常，结论与辅助信息有清晰层级。
4. 运行中、失败、无数据和断线时，真实状态可见，取消及重试等原有操作仍可用。
5. 历史、日志、个人中心和管理弹窗使用同一组件规范，键盘操作和焦点管理保持有效。
6. 在 1440px、1024px、390px 宽度检查布局：主要控件可操作，文本无遮挡，页面无横向溢出。

## 验证要求

先运行受影响组件的 Vitest，再运行 make frontend-test、make test 与 make build。用浏览器检查主工作台和可访问的弹窗；图表和分析数据不足时说明实际验证范围，不使用虚构数据宣称业务验证通过。若出现已有失败，记录输出并遵循项目 diagnosing-pa-errors 流程诊断。

验收阶段在本 Issue 目录创建 verification.md，记录命令输出、界面检查和剩余限制。没有最新验证输出不得宣称完成。
