# 模拟交易训练与真实交易回放

日期：2026-10-02
状态：设计方向已确认，书面规格待审阅；尚未实现。

## 1. 目标与已确认范围

用户要求增加回放交易，拆成两个独立功能，并选择完整训练版。

- 模拟交易训练：隐藏未来行情，在历史行情中自主下单，练习进出场和风险控制。
- 真实交易回放：按已有交易记录还原进出场和持仓过程，辅助复盘。
- 两个独立入口，共用行情与回放组件；模拟成交不写入真实交易日志。
- 完整训练包含市价单、限价单、撤单、止损、止盈、加减仓、盈亏统计与场次保存恢复。
- 下一根行情开始撮合，分钟行情驱动；同分钟无法判断止损止盈先后时止损优先。
- 本功能用于研究与复盘，不连接实盘经纪商，不自动触发 LLM 分析。

## 2. 现状与方案选择

现有 `useChartReplay.ts` 支持自选/随机起点、前后逐根、倍速和行情加载；`TradingChart.tsx` 内部持有回放状态。行情已有统一分钟归档。`trades/service.py` 保存每笔交易的开平仓摘要、方向、数量与费用，不是逐次成交账本。

选用“共享回放界面 + 后端训练撮合与持久化”：刷新恢复、并发控制和盈亏规则由后端统一保证。纯前端训练保存简单，但不适合可靠恢复与并发一致性；独立建设两套回放引擎会重复行情逻辑。

新增 `backend/app/replay/`，按 contracts、models、repository、engine、service、routes 分层。撮合引擎为不访问数据库的确定性领域逻辑。前端两个工作区共享回放控制器和图表展示；保留现有图表回放兼容入口，避免把新业务继续堆进 App 或 TradingChart。

## 3. 用户界面

### 模拟交易训练

- 独立导航入口，列出当前用户场次，可创建、恢复、查看已结束结果。
- 创建时选择品种、自选或随机起点、初始资金、每手每边手续费、滑点 tick 数。费用和滑点默认 0，界面明确显示；初始资金默认 100,000，币种 USD，可修改。
- 首版一场次一个品种，使用项目支持的 ES/NQ/MES/MNQ/MGC；合约最小价格变动和乘数经官方资料验证后固化并随场次保存。
- 中央行情图，底部播放/暂停/逐根/倍速/时间；右侧下单与持仓；下方订单、成交、资金曲线和训练统计。
- 下单支持多空、市价/限价、整数手数、可选止损和止盈；未成交限价单可修改或撤销，持仓保护价可修改。
- 支持同向加仓、部分或全部平仓；一个品种仅有净持仓，不同时持有多空。平仓为 reduce-only；反向开仓要求先平仓。
- 每次推进以一分钟为基准，显示周期可切换；一次最多一个推进请求，倍速不跳过撮合分钟。
- 回看仅移动观察游标，禁止在旧时间下单；回到最新训练进度后恢复操作。重新练习创建新场次。
- 切换功能或关闭页面保留最后已提交状态；刷新后暂停，手动继续。
- 结束训练要求已无持仓；有持仓时提供“提交全部平仓并推进到成交”，成功后结束。行情不足时保留场次，可稍后继续或放弃；放弃按最后价格保留未实现盈亏，不伪造成交。

### 真实交易回放

- 独立导航入口，交易日志增加“回放”入口。
- 选择单笔或同品种多笔交易；混合品种要求分开回放。
- 默认区间为最早开仓前 60 分钟到最晚平仓后 60 分钟，可调整；分钟数据不足时明确提示。
- 播放、暂停、倍速、逐根、时间定位，以及上一笔/下一笔成交；可自由回看。
- 成交事件按记录时间展示，时间相同使用稳定 ID 排序；进入某分钟时以该分钟结束为可见边界，保留成交原始时间。
- 播放到开仓才展示开仓标记，播放到平仓才展示退出标记和该笔最终盈亏；未来成交不在图表或动态明细提前出现。
- 开平仓摘要拆成两个展示事件；重叠交易按独立交易记录计算持仓，不把摘要推断成未记录的加减仓。
- 真实成交价与数量来自原记录。已实现盈亏优先展示导入报告值；若自行估算则明确标记“估算”，不重复扣减报告值中的费用。
- 现有行情按品种连续合约读取，无法保证与原记录实际到期合约一致：持续展示“连续合约行情”及原交易合约名称，不把差异解释为滑点；原始成交标记和报告盈亏不受影响，浮动盈亏仅标为参考估算。
- 创建回放时保存交易摘要快照，后续原交易修改不改变该场次；新场次读取最新记录。保存选择、区间和游标，可恢复。

## 4. 时间、撮合与盈亏规则

1. 内部统一 UTC；沿用图表显示时区。分钟 OHLC 的 timestamp 表示开盘时间；只有 `timestamp + 1 minute <= cursor` 的分钟已发生。
2. 后端训练接口只返回截止游标的行情；大周期蜡烛只由已发生分钟聚合，明确标记未完成，不能使用全周期高低收。
3. 下单时记录当前 cursor，订单不得与已揭示分钟撮合。市价单在下一可用分钟开盘价成交，买入加滑点、卖出减滑点。
4. 买入限价在下一分钟 open <= limit 时按 open 成交，否则 low <= limit 时按 limit；卖出对称。限价成交不得劣于限价，不额外施加滑点。
5. 止损为止损市价：跳空越过止损按开盘价加不利滑点，盘中触及时按止损价加不利滑点。止盈作为限价处理，跳空可按更优开盘价成交。
6. 原有持仓同分钟双触发且开盘不能确定先后时止损优先，并记录 ambiguity 标志。新开仓分钟同样按保守规则：止损触达即可触发，止盈仅在能确定发生于开仓之后时成交，否则留到后续分钟。开盘成交后的双触发止损优先。
7. 每分钟先处理已有保护单，再处理主动平仓，再按创建序处理开仓单，最后评估新持仓保护单。保护退出后当分钟不再执行开仓挂单，撤销这些挂单并记录原因，避免意外重新入场。
8. 加仓使用数量加权均价；一份净持仓共用一组止损止盈。加仓继承现有保护价，加仓表单不另设冲突保护；保护平仓数量随剩余持仓变化。一侧保护成交后另一侧撤销。
9. 价格必须符合 tick；数量为正整数；新仓保护价必须位于参考入场价正确两侧，持仓修改保护价以当前可见价格校验。跳空导致新仓保护已越界时按上述保守退出规则处理。
10. 金额使用 Decimal，API 金额用字符串；实现损益 = 方向 × 价差 × 合约乘数 × 手数。逐笔成交扣手续费；现金 = 初始资金 + 已实现毛利 - 已收费用；权益 = 现金 + 未实现盈亏。
11. 不模拟保证金、强平、排队与成交量部分成交；订单满足条件时全部成交。界面说明为分钟级撮合。
12. 训练统计包含已实现净利、未实现盈亏、权益、最大权益回撤、平仓次数和胜率。部分平仓每次算一笔平仓，胜率按分摊双边费用后净利为正计胜。
13. 连续合约 instrument_id 改变时暂停训练撮合并提示换月，不跨换月价格跳变成交；可放弃本场或从新合约时段新建。历史标识未知的数据展示来源限制。

## 5. 数据、接口与一致性

新增表：

- replay_sessions：用户 scope、mode、品种、配置与规则版本快照、行情游标、状态、revision、初始资金、持仓/资金状态、时间戳。
- replay_orders：方向、类型、意图、价格、数量、保护设置、有效时间、状态及原因。
- replay_fills：不可变成交价量、费用、时间、订单关联、歧义说明。
- replay_events：请求 operation_id、序号、状态变化、权益及撮合所用分钟 OHLC/来源快照；用于幂等恢复和结果解释，不重新用修订行情改写历史成交。
- replay_trade_snapshots：真实回放所选记录的不可变副本。

所有读写按已认证用户 scope 限制；未启用认证时沿用项目 local 身份。真实交易来源沿用现有交易日志权限，不在本 Issue 重构其归属，但不能借新接口扩大访问范围。

API 前缀 `/api/v1/replay`：

| 方法与路径 | 行为 |
| --- | --- |
| POST /sessions | 创建 training 或 historical 场次，校验参数并保存快照 |
| GET /sessions | 当前用户分页列表，每页默认 20、最多 100 |
| GET /sessions/{id} | 场次状态和最新 revision |
| GET /sessions/{id}/bars | 截止可见游标的行情，单页最多 2,000 根 |
| GET /sessions/{id}/events | 成交、订单、权益事件分页，每页最多 200 |
| POST /sessions/{id}/commands | 统一有类型命令：advance/place_order/amend_order/cancel_order/update_protection/finish/abandon/seek |

命令携带 operation_id 和 expected_revision。相同 operation_id 与相同内容返回原结果，不重复成交；相同 ID 内容不同返回 409。不同命令的过期 revision 返回 409，前端刷新场次后提示，不自动重复下单。

场次行锁内，订单、成交、持仓、权益、游标、revision 与幂等记录单事务提交。行情读取在锁外执行，提交前复查 revision。前端超时或取消不代表服务器未提交，重试使用相同 operation_id。

`seek` 对历史回放保存定位；训练只允许读已发生行情的观察定位，不回滚持仓和正式游标。推进每次最多处理一根可用分钟，后端可批量预取但不能提前返回未来 OHLC。

场次状态 active/completed/abandoned。active 表示可恢复，不表示浏览器持续自动播放。行情失败、超时不改变交易和游标，记录错误事件并暂停前端；本期不用后台分析任务，不引入悬空分析 Run。

新增数据采用增量建表方式，保留所有已有表；回退应用可忽略新表，场次数据保留。同步后端契约、前端 types/api 和接口测试，无新增产品依赖的默认计划。

## 6. 行情异常与可观测性

- 使用现有行情服务、归档与外部调用超时；同一场次前端最多一个加载/推进请求。
- 空窗口分批向后查找，每次最多 7 个自然日、最多 5 次查询；没有数据则暂停并显示可重试原因，不生成虚构分钟。
- 缺数不能一概当休市。覆盖状态显示未完成、供应商失败或存在已知采集缺口时暂停；正常空窗可跳过，同时显示前后时间间隔。
- 每次 API 沿用请求 trace_id，传递至 service/repository/行情边界。结构化记录 session_id、operation_id、revision、事件类型、结果、耗时；失败记录异常与堆栈，不记录完整交易正文。
- 不跨外部行情加载长期持有数据库锁。重复请求和冲突可通过 trace_id 与 operation_id 关联解释。

## 7. BDD 验收场景

1. 给定历史起点，创建训练后只能看到截止游标行情；切到大周期也没有未来高低点。
2. 给定当前可见 K 线，下市价单后不会用当前收盘价立即成交；推进后在下一分钟开盘按滑点成交。
3. 给定买入/卖出限价，未触及时保持挂单，触及时成交，跳空成交不劣于限价；撤单后不再成交。
4. 给定持仓止损止盈，同分钟双触发按止损执行并留歧义标志；跳空止损不按不可获得的止损价成交。
5. 给定同分钟新限价开仓和保护触达，不假设有利路径；覆盖不能确定先后的止盈延后场景。
6. 给定加仓、部分平仓，均价、剩余保护数量、手续费分摊、胜率和权益正确；不出现反向净仓。
7. 给定已发生成交，回看不能在过去下单；回到最新进度恢复操作，刷新后结果和挂单一致。
8. 给定重复 operation_id、网络超时重试或两个标签页并发，不出现重复成交；过期 revision 返回冲突。
9. 给定已导入交易，开平仓标记只在回放到事件后出现；跳转、回看、重叠交易持仓按记录还原。
10. 给定真实记录报告盈亏和费用，展示不重复扣费；连续行情与实际合约不同明确标注参考限制。
11. 给定已保存真实回放，原交易修改后该场次不变；新场次使用新记录。
12. 给定数据不足、上游超时、缺口或换月，停止推进并保留订单持仓，无虚构成交，可恢复或放弃。
13. 给定其他用户场次 ID，无权读取或写入；用户无法通过请求指定 owner 越权。
14. 给定结束或放弃场次，终态持久化且禁止再次下单；未知客户端提交结果可通过幂等查询恢复。
15. 给定错误调用，能通过同一 trace_id 关联 API、行情边界、失败日志及 session_id。
16. 现有普通图表回放、分析历史查看、交易导入与交易日志功能保持可用。
