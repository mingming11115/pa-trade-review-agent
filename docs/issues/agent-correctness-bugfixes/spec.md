# Agent 正确性与终态缺陷修复

## 授权与范围

2026-09-30，用户在代码评审列出七项优先缺陷后明确要求修复。本文件记录已批准的修复范围，不新增功能或改变一次性 Task / 平铺 Run 模型。

1. 最新已收盘行情工具对齐周期边界，避免截断高周期 OHLCV。
2. 取消在启动前、读取运行期间、其他 Worker 收到请求时均能形成持久化终态。
3. 持久化层原子检查 Run 状态转换，终态不可重新打开或覆盖。
4. 历史工具继承服务端认证用户身份，匿名请求保持匿名范围。
5. 工具循环为最终回答预留一次禁用工具的请求；不能生成最终回答时明确失败，不保存中间文字为答案。
6. Task 聚合保留 Run 的部分成功或降级信息。
7. 前端按终态处理结果，展示失败、取消、超时及部分成功；同步必要的后端详情字段和前端类型。

## 验收场景

- 当前 10:07，查询两根 5 分钟已收盘棒，应得到 09:55、10:00 的完整行情，不能截止到 10:02。
- 取消发生在协程首次执行之前或首次读取期间时，不能永久停留 queued / cancel_requested；另一个执行管理器收到取消后，运行端最终停止。
- completed / failed / cancelled / timed_out 等终态不能再转 running，迟到完成不得覆盖已持久化取消。
- 用户 A 的工具查询只看 A 的历史，B 不可见；模型提供 user_id 不能改变权限；请求结束还原身份上下文。
- 三轮工具调用后允许一次基于全部观察结果的最终回答；若仍要求调用工具，返回预算耗尽错误，无 done 或成功回答持久化。
- 仅有 completed_with_warnings 或 degraded Run 的 Task 不能显示完全成功。
- 失败 Run 即使带有 bars / llm_transcript，也不会被前端当作完整分析结果解析；失败信息可见。

## 技术边界

复用现有异步管理器、数据库和错误契约，使用数据库状态条件保证并发写入安全；取消意图由运行端观察。工具身份只由服务端上下文传递，不进入模型可选择参数。保持 trace_id 贯穿现有链路，错误不暴露敏感内容。

不新增依赖、任务队列或数据库迁移；不包含进程崩溃后的自动恢复、完整评估平台或其他架构优化。运行期取消与进程强制终止是不同故障场景，后者另行设计。

## 验证

先为每项缺陷建立失败回归，再做最小修复；使用隔离数据库和模拟模型验证，不操作真实业务数据库。局部测试后运行 make test、make build 和 git diff --check；记录实际结果与剩余限制。
