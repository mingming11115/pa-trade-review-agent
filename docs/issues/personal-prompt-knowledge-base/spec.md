# 个人提示词知识库

状态：两阶段已实施；个人数据库管理页面、保存、历史与回滚完成，验证证据见 verification.md。

## 优先里程碑：存量提示词转知识库并验证分析

根据用户最新要求，先完成存量内容的数据层与分析集成，再开展个人管理页面实现。

- 用户提到的 prompt.py 在当前仓库对应 backend/app/llm/prompts.py 及其引用的 prompt_engineering/*.txt。实际分析入口使用 Stage1/Stage2 adapter 和 PromptAssembler，必须接入实际工作流，不能只改旧 prompts.py。
- 将现有工作流引用的 TXT 内容原样导入数据库默认知识条目，每个条目以原文件名作为稳定标识，并创建第一版历史记录。导入以首次成功内容为准，可重复执行但不得覆盖已存在条目或修订。参考目录 _reference 不导入。
- 默认条目属于系统模板；个人编辑产生本人覆盖内容与历史，其他用户继续使用数据库默认条目。用户尚无覆盖时加载默认条目，运行期间保持快照一致。
- 在导入完成的知识库路径中，分析从数据库快照获取提示词，TXT 文件保留为初始化来源和回退旧代码时的资料，不作为同一运行的混合来源。数据库缺失必要条目或读取失败返回明确错误，不能静默跳回文件。
- 第一里程碑验证所有条目导入前后内容一致，原样默认知识库生成的 Stage1/Stage2 消息与文件版本一致，并通过真实分析编排的测试验证两个阶段能使用知识库内容。
- 自动测试可用可控 LLM 响应验证编排与结构化校验；若没有可用模型凭据或行情服务，不声称已完成外部模型端到端验证，并记录实际限制。
- 个人页面及完整 API 作为后续里程碑，保留本设计中的用户隔离、版本历史与回滚要求；新增条目和加载条件配置仍仅记录到 todo.md。

## 目标与范围

用户通过页面编辑项目现有的分析提示词，修改只影响自己的后续分析，无需修改服务器文件。所有登录用户均可使用个人知识库管理页面；管理员编辑个人内容时也遵循同样的用户隔离规则。

第一版仅编辑现有分析工作流引用的 TXT 文件，保留现有阶段、拼接顺序和策略路由。不支持新增、删除、重命名条目、文件上传、向量检索或自行配置加载条件。新增条目及加载条件配置已记录在根目录 todo.md。

## 当前实现与方案选择

现有后台在 backend/app/admin/prompts.py 中直接读写共享文件，版本记录不包含所有者；前端入口仅管理员可见。PromptAssembler 的系统提示词缓存以目录为键，无法隔离个人内容。

采用数据库存储默认条目与个人覆盖内容、项目文件作为首次导入来源的方案。相比每用户复制目录，该方案更适合事务更新、版本回滚和多实例部署；相比完整知识检索系统，能保留已有分析行为，满足当前已确认范围。

## 数据与权限

- 新增个人提示词当前内容与不可变历史版本，均按所有者和文件名隔离；所有者使用登录用户 UUID，不接受客户端指定其他所有者。
- 未修改的条目读取数据库默认模板；首次保存时同时保存当时的默认内容作为个人初始历史版本，随后记录个人新版本。
- 内容保存、历史追加在同一数据库事务完成。使用版本号进行乐观并发检查，冲突返回 409，页面保留未保存内容并提示刷新。
- 回滚只能选取本人同一文件的历史版本，并作为一次新修订记录操作人和时间。
- 文件范围沿用工作流引用文件白名单，拒绝路径穿越、任意文件访问和空白内容；内容上限沿用现有 1,000,000 字符限制。
- 未启用认证时使用独立 local 所有者作用域；共享部署必须开启认证才能实现多人隔离。
- 保留共享模板和现有全局版本数据，不迁移为任意用户私有数据，不删除旧表。个人管理接口不调用共享文件写入逻辑。

## API 与页面

在个人知识库 API 中提供条目列表（含阶段和加载条件）、内容读取、保存、历史列表和回滚，身份取自 current_user。采用现有前后端数据契约风格，在 frontend/src/api.ts 和 types.ts 同步定义。

页面对所有登录用户提供“个人知识库”入口，左侧直接展示去重后的全部提示词文件、总数及文件名搜索，右侧编辑所选条目。顶部提供“提示词编辑”和“阶段与加载说明”视图切换；说明页占据完整内容区域，左侧选择阶段，右侧展示用途、提示词文件和加载条件，窄屏改为横向阶段选择与独立正文滚动。返回编辑保留未保存草稿，切换阶段从说明顶部开始。编辑页展示默认模板/个人版本来源、版本历史与回滚。保存成功提示“仅影响自己的后续分析”。现有管理员共享模板接口保留为兼容能力，个人入口不使用这些写接口。

## 分析集成

- 从持久化 Run 的 user_id 解析所有者，不依赖后台任务中的请求身份，也不接受调用方随意指定用户。
- 每次 Run 开始执行时，批量解析该用户的有效提示词，形成不可变运行快照；同一 Run 的 Stage1、Stage2、重试及复盘子处理共用该快照。
- 正在运行时用户保存内容不会改变该 Run；保存成功后的下一次 Run 使用新内容。
- 为 PromptAssembler 增加显式内容注入，保留默认文件加载以兼容原有调用。个人系统提示词缓存按有效内容摘要隔离，避免不同用户或版本串用；缓存必须有容量边界。
- 检查所有分析及预览调用入口，使其使用本人有效内容；不修改追问助手本身的提示词，因为不属于当前固定文件目录。
- 阶段 prompt_metadata 记录使用的文件名、来源和内容摘要，便于追踪；不在普通日志中输出完整个人提示词。
- 个人提示词读取失败时不能静默使用默认模板，分析按已有失败路径保存持久化终态。用户修改不会绕过程序输出契约和结构化校验。

## BDD 验收场景

1. Given 用户未编辑条目，When 打开个人知识库，Then 显示对应默认模板与阶段加载说明。
2. Given 用户 A 保存个人条目，When 用户 B 读取同一条目或执行分析，Then B 的内容不受 A 修改影响，共享文件也未改变。
3. Given 普通登录用户，When 打开个人知识库并保存，Then 无需管理员权限即可管理本人的内容。
4. Given A 的修订已存在，When B 尝试读取或回滚 A 的版本 ID，Then 请求被拒绝且不泄漏内容。
5. Given 两个编辑页面打开同一版本，When 第一页保存后第二页保存，Then 第二页收到冲突提示且保留编辑内容。
6. Given 用户有历史版本，When 回滚，Then 当前内容恢复且产生新修订，历史保留。
7. Given Run 已开始，When 用户保存新内容，Then 当前 Run 两阶段使用原快照，下一次 Run 使用新内容。
8. Given 两个用户交错执行分析，Then 系统提示词和策略内容均来自各自快照，缓存不发生串用。
9. Given 数据库读取失败，When 执行分析，Then Run 保存失败终态，不能伪装为使用默认模板的成功分析。
10. Given 空白、超限内容或非法文件名，When 保存，Then 返回明确错误且当前内容及历史均不变。
11. Given 用户有未保存草稿，When 打开阶段说明并返回编辑，Then 草稿保留；说明页可独立选择阶段，查看对应文件与加载条件，无提示词的阶段明确说明。
